# アプリ本体 (`app/pwa`)

iPhone の Safari で開き、ホーム画面に追加して使う PWA です。
macOS も Apple Developer アカウントも不要で、オフラインで動きます。

```bash
cd app/pwa
npm install
npm run sync-data   # out/ の生成物を public/ へ取り込む
npm run dev         # 開発サーバー
npm run build       # dist/ に本番ビルド
```

パイプラインを再実行したら `npm run sync-data` も実行してください。

## 画面構成

タブは3つです。**パート選択は「学習」タブの中**にあります
（別タブに分けると、どちらを開けばよいか分かりにくいため）。

| 画面 | 内容 |
|---|---|
| 学習 | 上部にパート表示 → 押すとパート選択 → 選ぶとそのまま学習に入る |
| 統計 | 今日の解答数・正答率・定着度分布・苦手な語・判定のずれ |
| 設定 | バックアップ、キーボード、発音、**出典表示**（ライセンス必須）、データ消去 |

学習画面は 英単語 → かなキーボードで入力 → 3値判定。
`unsure`（惜しい）のときは「合ってた？」でユーザーが自己申告します。

## ひらがな専用キーボード (`src/kana-keyboard.ts`)

**`<input>` 要素を一切使っていません。** OS の IME を経由しないので、
漢字やカタカナへの変換が構造的に起こりえません。
文字列はキーボードのクラスが完全に保持し、表示は div で行います。

**フリック入力とトグル入力の両方で打てます。**

- **タップ** — 同じキーを続けて押すと `あ→い→う→え→お` と巡回する（トグル入力）。
  0.9秒空けるか別のキーを押すと、次の文字として足される。
  **設定 ＞ キーボード で切れる**（切ると、タップは常に中央の文字）
- **フリック** — 上下左右にはじくと、その方向の文字が1回で入る

フリックだけにしないのには理由が2つあります。フリックが苦手な人でも打てる
ようにするためと、**フリック入力には日本で特許が成立している**ためです
（2007年出願、2011〜2013年に登録、現在も存続）。唯一の入力手段にすると
その権利に依存することになります。トグル入力は携帯電話で古くから使われて
きた方式で、単独で完結します。

```
あ  か  さ  ⌫
た  な  は  ん
ま  や  ら ┌────────┐
ー  わ  小゛゜│ こたえる │
           └────────┘
```

- キーを押している間、上下左右にどの文字があるかを十字で表示する
- 横 14px / 縦 20px 以上動かした方向の文字が確定する。動かさなければ中央の文字。
  横のほうが小さいのは、画面の端の列（`あ` から左など）では画面の外へ向かって
  指を動かすことになり、動かせる幅がそもそも足りないため
- `ん` と `ー` は頻出なので専用キーにしてある（`わ` からのフリックでも出せる）
- `小゛゜` キーは直前の文字を巡回させる
  （`か→が`、`は→ば→ぱ`、`つ→っ→づ`、`や→ゃ`）
- 「こたえる」は右列の縦長ボタン

## パート分割

頻度順の全1,883語を100語ずつ19グループに分けてあります
（グループ1が最も易しい）。**一度に1パートだけ**を出題対象にします。

パートを変えると、その語だけでスケジューラを組み直します
（`buildScheduler`）。出題も進捗もそのパートに閉じます。

## ストレージ退避への対策

iOS はホーム画面アプリの保存データを消すことがあります。学習記録が
消えるのは致命的なので、二重に守っています。**どちらも削除しないでください。**

- 起動時と設定画面から**永続ストレージを要求**する（`navigator.storage.persist`）
- 設定画面と共有シートからの **JSON エクスポート／インポート**

## 配信

`dist/` は静的ファイルなので、GitHub Pages などに置けます。
**PWA のインストールには HTTPS が必須**です。
サブディレクトリに置く場合はベースパスを指定します。

```bash
PWA_BASE=/repo-name/ npm run build
```

## Swift 版について（現在は未使用）

`app/VocabKit/` に Swift 移植があります。macOS が無いため使っていませんが、
Windows で動かす際に踏んだ問題を記録しておきます。

| 症状 | 原因と対処 |
|---|---|
| `could not find CLI tool 'link'` | MSVC のリンカが必要。`swift-env.ps1` が Visual Studio の `vcvars64.bat` を読み込む |
| `unable to load standard library` | `SDKROOT` 未設定。`vcvars64.bat` が環境変数を組み替えるため、その後に設定し直す必要がある |
| `.ps1` が文字化けして構文エラー | PowerShell 5.1 は BOM 無し UTF-8 を ANSI として読む。**`.ps1` は UTF-8 BOM 付きで保存する** |
| `tools version 3.1.0 which is no longer supported` | 逆に **`Package.swift` は BOM を付けてはいけない**。BOM があると先頭の `// swift-tools-version:` が読めない |
| `swift test` が固まる | Windows のテスト検出の不具合。`verify.ps1` を使う。XCTest は macOS 用に残してある |
| `unable to create symbolic link` の警告 | 無害。Windows でシンボリックリンクを作るには開発者モードが要るだけで、ビルドは成功している |

PowerShell 5.1 では native コマンドに `2>&1` を付けると stderr が
エラー扱いになり、終了コード 0 でも失敗と判定されます。
`swift build` は警告を stderr に出すので、リダイレクトせず
`$LASTEXITCODE` で判定してください。
